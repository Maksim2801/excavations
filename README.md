# Полевые описи археологических находок

Клиент-серверное веб-приложение для полевого учёта раскопов, пластов и находок: координаты, фотоанализ размеров, план, импорт GNSS и полевые описи в Excel и PDF.

## Запуск

Нужны Docker и Docker Compose. Из корня проекта:

```bash
docker compose up --build
```

При старте контейнер дожидается PostgreSQL, применяет миграции Alembic, загружает демонстрационные данные и поднимает сервер.

- интерфейс: http://localhost:8000
- API: http://localhost:8000/api
- Swagger: http://localhost:8000/docs

Панель Stagewise (расширение IDE Bridge) подключается отдельной командой, когда сервер уже запущен. Нужен Node.js. Из корня проекта:

```bash
npm run stagewise
```

Панель открывается на http://localhost:3100 и проксирует интерфейс с порта 8000. Выбранный элемент уходит в агент Cursor. Версия CLI зафиксирована на 0.11.1: команда `npx stagewise@latest` сейчас только предлагает скачать отдельное приложение и панель не поднимает.

Остановка: `docker compose down`. Данные базы сохраняются в томе `pgdata`.

Параметры окружения описаны в `backend/.env.example`. В Compose они уже заданы: база `archaeology` / `archaeology`, PostGIS 16, порт API `8000`, порт PostgreSQL `5432`.

## Демонстрационные пользователи

| Логин | Пароль | Роль |
| --- | --- | --- |
| field_arch | FieldArch1 | полевой археолог |
| camera_arch | CameraArch1 | камеральный сотрудник |
| supervisor_arch | SuperArch1 | руководитель работ |

Регистрация через интерфейс создаёт только полевого археолога. Пользователей остальных ролей добавляет руководитель.

Демонстрационные раскопы: `R-1` / 2024 и `SH-2` / 2025, пласты, 18 находок, угловые и контрольные GNSS-точки, фотографии с масштабной линейкой. У одной находки размер уже принят по фото.

## Тесты

```bash
docker compose exec backend pytest
```

Модульные тесты (формула размера, распознавание маркера, разбор CSV, контракт интерфейса) не требуют отдельной настройки. API-тесты создают базу `archaeology_test`, накатывают миграции и очищают таблицы перед каждым тестом. Если PostgreSQL недоступен, API-тесты пропускаются.

## Роли

Полевой археолог ведёт находки, координаты, фото, измерения, план, фильтры и импорт GNSS. Камеральный сотрудник дополнительно правит пласты и описания, переводит измерение в ручное, выгружает описи. Руководитель создаёт и архивирует раскопы, ведёт справочники и пользователей, подтверждает описи.

## Ограничения

- Координаты хранятся в локальной метрической системе, SRID 0, без пересчёта в другую систему координат. Ось X - East, ось Y - North, Z - Elev.
- Раскопы общие для всех вошедших пользователей. «Рабочий раскоп» в интерфейсе - только выбранный контекст браузера.
- Автопоиск находит контрастную масштабную полосу и самый крупный тёмный контур предмета. Длину маркера в миллиметрах вводит пользователь. Толщина по одному снимку сверху не определяется. Линии нужно проверить и принять.
- Файлы фотографий и описей лежат на диске контейнера (`backend/uploads`, `backend/reports`), не в объектном хранилище.
- Выход из системы очищает токен в браузере и пишет событие в журнал. Отдельного списка отозванных токенов нет.
- Нестабильная связь закрывается черновиком формы и ключом идемпотентности, а не полной офлайн-очередью.
- У находки один способ измерения. Если по фото принята хотя бы одна ось, способ становится «по фото».
