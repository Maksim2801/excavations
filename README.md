# Полевые описи археологических находок

Веб-приложение для **автоматизированного составления полевых описей археологических предметов**: структурированный ввод и хранение данных о находках, фотофиксация, локализация по раскопам и пластам (координаты North/East/Elev), фотоанализ габаритов и формирование унифицированных выходных документов (Excel/PDF).

Назначение и состав функций соответствуют ВКР *«Разработка веб-приложения для автоматизированного составления полевых описей археологических предметов»* (гл. 2: п. 2.1–2.2, 2.6). Практические сценарии обновления базы: [docs/UPDATE.md](docs/UPDATE.md).

---

## Функциональность

Согласно п. **2.1**, система объединяет координатную привязку, послойную документацию и фотоанализ габаритов в непрерывном цикле: от регистрации находки в раскопе до отчётного списка. Функциональные требования сгруппированы по модулям (п. **2.2**, детализация интерфейса - п. **2.6**).

### Модуль «Раскопы и пласты»

- создание, редактирование и архивирование карточек раскопов (шифр, год работ, координаты центра, описание);
- справочник пластов внутри раскопа (номер, верхняя/нижняя отметки Elev, характеристика слоя, цветовое кодирование);
- контроль целостности: нельзя удалить раскоп или пласт при наличии связанных находок.

### Модуль «Опись»

- регистрация находки с кодом по схеме «шифр раскопа + год + порядковый номер»;
- привязка к раскопу и пласту, ввод North/East/Elev, габаритов и описания;
- табличный перечень с настраиваемыми колонками, сортировкой и фильтрацией (раскоп, пласт, способ измерения, наличие фото и др.);
- индикация способа измерения (ручное / по фото) и связанных фотографий;
- подсветка неполных записей (нет координат, габаритов или фото);
- пакетный экспорт выбранных записей в Excel/PDF.

### Модуль «План»

- план раскопа по координатам находок и GNSS-точек (scatter-plot, система North/East/Elev);
- цветовое кодирование по материалу и/или пласту; переключатель «все пласты / текущий пласт»;
- масштабирование, панорамирование, координаты курсора, всплывающие подсказки (код, пласт, материал, габариты);
- переход из точки плана к карточке в описи.

### Модуль «Фотоанализ»

- загрузка фотографий с привязкой к записи описи (и послойная фотофиксация пластов);
- измерение по фото: распознавание масштабного маркера, коэффициент мм/пиксель, длина и ширина;
- передача габаритов в карточку с отметкой «измерено по фото»; ручная корректировка линий и результатов;
- при неудачном распознавании - переход к ручному вводу или другой снимок.

### Модуль «GNSS-импорт»

- загрузка координатных файлов (универсальный CSV-импорт);
- привязка точек к раскопу с типом (угловая, контрольная, вспомогательная);
- использование точек на плане и при проверке координат находок.

### Модуль «Отчёты»

- описи по фильтрам (раскоп, пласт, материал, способ измерения и др.);
- экспорт Excel и PDF с унифицированными колонками, единицами и оформлением;
- сохранение шаблонов отчётов для повторного использования в следующих сезонах.

### Роли пользователей (п. 2.2, 2.6)

| Роль | Основные права по диплому |
| --- | --- |
| **Полевой археолог** | Создание и правка находок в своём раскопе; координаты и габариты; фото и измерение по фото; просмотр плана |
| **Камеральный сотрудник** | Правка описаний и пластов; корректировка измерений (в т.ч. перевод «по фото» → «ручное»); отчёты и экспорт |
| **Руководитель работ** | Создание/закрытие раскопов; справочники; пользователи и роли; подтверждение итоговых отчётов |

### Нефункциональные требования (п. 2.2)

- работа через браузер на ПК и планшетах, адаптивная вёрстка;
- устойчивость к нестабильной связи: кэш при кратких обрывах, корректная повторная отправка;
- измерение по фото - порядка нескольких секунд на типовой снимок;
- целевая погрешность автоизмерения - порядка 1–2 мм (при корректном маркере, объекты до ~100 мм);
- разграничение прав, авторизация, защита от несанкционированного изменения данных.

```
┌──────────────────────────▼──────────────────────────────┐
│  Backend (FastAPI)                                      │
│                                                         │
│  api  →  services  →  repositories  →  models           │
│   │         │              │              │             │
│  HTTP    бизнес-        доступ к       SQLAlchemy /     │

└──────────────────────────┬──────────────────────────────┘
                           │
┌──────────────────────────▼──────────────────────────────┐
```

### Слои backend

| Слой | Путь | Назначение |
| --- | --- | --- |
| **API** | `backend/app/api/` | Маршруты HTTP, валидация запросов, авторизация |
| **Services** | `backend/app/services/` | Бизнес-логика: находки, фото, GNSS, отчёты, план |
| **Repositories** | `backend/app/repositories/` | Запросы к БД и выборки |
| **Models** | `backend/app/models/` | ORM-модели SQLAlchemy |
| **Schemas** | `backend/app/schemas/` | Pydantic-схемы ввода/вывода |
| **Auth** | `backend/app/auth/` | JWT, зависимости ролей |
| **Utils** | `backend/app/utils/` | Экспорт, геометрия, измерения, файлы |
| **Migrations** | `backend/migrations/` | Alembic-миграции схемы |

### Frontend

| Часть | Путь | Назначение |
| --- | --- | --- |
| **Modules** | `frontend/modules/` | Экраны: вход, раскопы, находки, план, описи, админка |
| **Services** | `frontend/services/` | API-клиент, кэш сессии, демо-режим |
| **Hooks** | `frontend/hooks/` | Запросы и состояние интерфейса |

Сервер отдаёт статику фронтенда с того же порта, что и API (`8000`).

## Технологии

### Backend

- **Python 3.12**, **FastAPI**, **Uvicorn**
- **SQLAlchemy 2**, **Alembic**, **psycopg 3**
- **PostgreSQL 16** + **PostGIS** (GeoAlchemy2, Shapely)
- **Pydantic** / pydantic-settings
- **PyJWT**, **bcrypt** - авторизация
- **OpenCV**, **Pillow**, **NumPy** - фотоанализ размеров
- **pandas**, **openpyxl**, **ReportLab** - Excel и PDF

### Frontend

- **React** (production-сборка в `vendor/`)
- **HTM** - JSX-подобные шаблоны без сборщика
- Модульный ES-клиент без Node-бандлера для продакшена

### Инфраструктура

- **Docker** / **Docker Compose**
- **pytest**, **Playwright** - тесты API и браузера
- **GitHub Actions** - CI с PostGIS

## Быстрый старт (Docker)

### 1. Клонировать репозиторий

```bash
git clone https://github.com/Maksim2801/excavations.git
cd excavations
```

### 2. Запустить контейнеры

```bash
docker compose up --build
```

При старте backend:

1. дожидается готовности PostgreSQL  
2. применяет миграции Alembic  
3. загружает демонстрационные данные (`seed`)  
4. поднимает Uvicorn на порту `8000`

### 3. Открыть приложение

| Адрес | Назначение |
| --- | --- |
| http://localhost:8000 | Интерфейс |
| http://localhost:8000/api | REST API |
| http://localhost:8000/docs | Swagger (OpenAPI) |

### 4. Остановка

```bash
docker compose down
```

Данные PostgreSQL сохраняются в томе `pgdata`. Фотографии и отчёты - в `backend/uploads` и `backend/reports`.

## Запуск без Docker

Нужны Python 3.12 и PostgreSQL 16 с PostGIS.

### 1. База данных

Создайте пользователя и БД (имена можно изменить, тогда поправьте `.env`):

```sql
CREATE USER archaeology WITH PASSWORD 'archaeology';
CREATE DATABASE archaeology_db OWNER archaeology;
```

Включите PostGIS в базе `archaeology_db`.

### 2. Окружение backend

```bash
cd backend
copy .env.example .env
```

На Linux/macOS: `cp .env.example .env`.

Проверьте `DATABASE_URL`, `JWT_SECRET`, `UPLOAD_DIR`, `REPORT_DIR`, `FRONTEND_DIR` в `.env`.

### 3. Зависимости и миграции

```bash
pip install -r requirements.txt
alembic upgrade head
python -m app.seed
```

### 4. Сервер

```bash
uvicorn app.main:app --host 127.0.0.1 --port 8000
```

Интерфейс: http://127.0.0.1:8000

## Демонстрационные пользователи

| Логин | Пароль | Роль |
| --- | --- | --- |
| `field_arch` | `FieldArch1` | полевой археолог |
| `camera_arch` | `CameraArch1` | камеральный сотрудник |
| `supervisor_arch` | `SuperArch1` | руководитель работ |

Регистрация через интерфейс создаёт только полевого археолога. Остальные роли добавляет руководитель.

В демо-базе: раскопы `R-1` / 2024 и `SH-2` / 2025, пласты, 18 находок, GNSS-точки и фотографии с масштабной линейкой.

Полевой археолог работает в **назначенных** раскопах; камеральный сотрудник и руководитель - во всех. После обновления существующей базы назначения задаются в разделе «Пользователи».

```bash

# с обязательным PostGIS
docker compose exec -e REQUIRE_POSTGIS_TESTS=1 backend pytest -q

# модульные тесты фронта
npm install
```

## Ограничения

- Координаты - локальная метрическая система, SRID 0 (X - East, Y - North, Z - Elev), без пересчёта в другие СК.
- Автоизмерение ищет контрастную масштабную полосу и крупный тёмный контур; длину маркера в мм вводит пользователь; толщину по одному виду сверху не получить.
- Фото и описи хранятся на диске (`backend/uploads`, `backend/reports`), не в объектном хранилище.
- При обрыве связи доступен кэш сессии (до 24 ч) и черновик новой находки; полной офлайн-очереди записи нет.
- У находки один способ измерения: если принята ось по фото, способ становится «по фото».
