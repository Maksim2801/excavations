# Обновление проекта по требованиям диплома

React и разделение сервера на api, services, repositories и models сохранены.
Обновление добавляет миграцию 0011_diploma поверх существующей 0010_reports_dict.

## Установка

1. Сохраните резервную копию действующей базы и каталогов backend/uploads и backend/reports. Не удаляйте Docker-том pgdata.
2. Перенесите исходники обновлённого проекта в рабочую папку. Сохраните свой backend/.env, загрузки и отчёты.
3. Выполните из корня проекта:

```bash
docker compose up --build -d
docker compose logs backend
```

При запуске применяется миграция Alembic. Для запуска без Docker:

```bash
cd backend
pip install -r requirements.txt
alembic upgrade head
python -m app.seed
uvicorn app.main:app --host 127.0.0.1 --port 8000
```

Используйте свои DATABASE_URL, JWT_SECRET, UPLOAD_DIR, REPORT_DIR и FRONTEND_DIR.
Существующие находки, фотографии и отчёты миграция не удаляет.
После установки войдите руководителем, откройте «Пользователи» и назначьте каждому полевому археологу его раскопы. В существующей базе назначения из соображений корректности доступа не создаются автоматически. Камеральные сотрудники и руководители имеют доступ ко всем раскопам. В новой демонстрационной базе назначения создаёт seed.

## Изменения

- Сервер ограничивает чтение и изменение находок, пластов, фотографий, GNSS и планов назначенными раскопами для полевого археолога.
- Опись позволяет выбирать колонки, сортировать отображаемые поля, отбирать по дате регистрации (UTC) и отмечать отдельные записи.
- Экспорт получает все фильтры и сортировку описи, включая поиск и отсутствие фотографий. Отмеченные записи дополнительно пересекаются с фильтрами.
- Шаблоны отчётов восстанавливают фильтры, сортировку, заголовок, реквизиты и колонки. Список отдельных отмеченных ID не сохраняется в сезонный шаблон.
- В отчёт добавлены реквизиты коллекции, памятника, автора раскопок, источника поступления, датировки, культурной принадлежности и примечаний.
- План поддерживает перетаскивание, масштаб, сброс вида, координаты курсора и подсказки с пластом и размерами. Цвет берётся из карточки пласта.
- GNSS-точку можно выбрать в карточке находки: сервер проверяет раскоп, копирует координаты и сохраняет связь. Ручная правка координат снимает эту связь.
- Новая находка может получить код вида «шифр-год-номер» и следующий номер на сервере. Конкурирующие операции создания сериализуются блокировкой раскопа.
- Добавлено развёрнутое описание. Поле description остаётся кратким описанием; API также возвращает short_desc и auto_measured для сопоставления с дипломной моделью.
- Фотографии сортируются по категории, времени загрузки и ID.
- В режиме «Сервер» обрыв связи не переключает приложение на демонстрационные данные. Ранее загруженные списки, карточки и планы доступны из кэша этой сессии до 24 часов, с предупреждением. При восстановлении соединения чтение повторяется.
- Черновик новой находки и ключ повторного запроса сохраняются в браузере. Повторное создание с тем же ключом возвращает прежний результат; изменённое содержимое с использованным ключом отклоняется. Создание находки и запись результата повторного запроса фиксируются одной транзакцией.
- При выходе очищаются кэш сессии и черновики пользователя. Полноценной автономной базы, фоновой очереди записи и офлайн-загрузки фотографий нет. Для сохранения изменений требуется соединение.

## Проверки

```bash
docker compose exec -e REQUIRE_POSTGIS_TESTS=1 backend pytest -q
npm install
npm run test:unit
npx playwright install chromium
npm run test:browser
```

Браузерные тесты запускают локальный FastAPI самостоятельно (порт 8088) и используют контролируемые HTTP-ответы. Это проверка интерфейса, а не замена интеграционным тестам с PostGIS. Для указания Python используйте TEST_PYTHON, для уже запущенного сервера TEST_BASE_URL.

В GitHub Actions добавлен запуск тестов с PostGIS. В CI отсутствие базы считается ошибкой, а не успешным пропуском. Локально без базы пространственные API-тесты пропускаются с явным статусом skipped.

## Фотоизмерения

Алгоритм определяет масштаб и длину/ширину на контрастном снимке. Результат необходимо проверить и принять. Толщина по единственному виду сверху не определяется: нужен боковой снимок с масштабом либо ручное измерение.

Исправлен пропуск крайней светлой секции масштабной линейки. Если светлая секция сливается с фоном и её границу нельзя уверенно определить, алгоритм требует ручной калибровки вместо выдачи недостоверных размеров.

Для проверки порога 2 мм и времени 3 секунды подготовьте CSV с реальными снимками:

```csv
image,scale_mm,length_mm,width_mm
photos/find-001.jpg,100,75,30
```

```bash
cd backend
python scripts/evaluate_photos.py samples.csv --out measurements.csv
```

Контрольные размеры снимаются независимо, например штангенциркулем. Программа считает ошибки и время по каждому снимку; непрочитанные и нераспознанные снимки также включаются в итог как неуспех. Синтетические модульные тесты не доказывают точность на реальных археологических предметах.

## Согласование текста диплома

Сам файл диплома этим обновлением не изменяется. В приложениях А и Б необходимо заменить прежние листинги на текущие файлы репозитория; архитектуру React и api/services/repositories/models описывать как выбранную реализацию. Таблицу модели уточнить: short_desc представлен полем description, auto_measured вычисляется из measurement_method. Заявления о точности и скорости должны опираться на протокол испытаний реальных снимков, а не на наличие алгоритма.
